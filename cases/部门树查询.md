# 部门树查询 — PostgreSQL

> 与 MySQL 的递归写法对比见 [../test_sql_mysql8/cases/部门树查询.md](../../test_sql_mysql8/cases/部门树查询.md)。
> 本文档所有 SQL 已在 GitHub Actions 的 PostgreSQL 中实际执行验证。

PostgreSQL 使用 **`WITH RECURSIVE`** 递归 CTE，语法与 MySQL 8.0 基本一致，另有特有的 **`CYCLE` 子句**自动检测循环引用，无需像 MySQL 那样手工加深度限制。

## 核心：向下查部门树（含路径与层级）

```sql
WITH RECURSIVE dept_tree AS (
    SELECT id, name, parent_id, 1 AS level,
           CAST(name AS VARCHAR(200)) AS path
    FROM departments
    WHERE id = 2              -- 锚点：技术部
    UNION ALL
    SELECT d.id, d.name, d.parent_id, dt.level + 1,
           dt.path || ' > ' || d.name
    FROM departments d
    INNER JOIN dept_tree dt ON d.parent_id = dt.id
)
SELECT id, parent_id, level, path FROM dept_tree ORDER BY path;
```

## PostgreSQL 特有：CYCLE 防死循环

数据存在错误闭环（A 的父是 B，B 的父又是 A）时，MySQL 会无限递归直到 `cte_max_recursion_depth` 报错；PG 可直接用 `CYCLE` 子句自动终止：

```sql
WITH RECURSIVE dept_tree AS (
    SELECT id, name, parent_id, 1 AS level,
           CAST(name AS VARCHAR(200)) AS path,
           ARRAY[id] AS path_ids
    FROM departments WHERE id = 2
    UNION ALL
    SELECT d.id, d.name, d.parent_id, dt.level + 1,
           dt.path || ' > ' || d.name,
           dt.path_ids || d.id
    FROM departments d
    INNER JOIN dept_tree dt ON d.parent_id = dt.id
) CYCLE id SET is_cycle USING path_ids
SELECT id, name, level, is_cycle FROM dept_tree;
```

## 其他差异点

- PG 的 `WITH RECURSIVE` 递归部分**可以**使用 `ORDER BY`/`LIMIT`（MySQL 不行）
- 路径拼接用 `||` 运算符；`ARRAY[id]` + `CYCLE ... USING` 是 PG 特有的循环检测语法
- `parent_id` 上建索引同样重要（逐层 JOIN 的性能关键）
